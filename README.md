wordfreq —— 命令行文本词频统计器
一个用 C 语言编写的命令行小工具：统计指定 txt 文件中出现频率最高的前 N 个「词」，
按 `序号. 单词 数量` 的格式输出。支持中英文及多语种混排文本，按作业文档的全部规则实现。
运行环境：Windows 11 + MinGW-w64 gcc（已在 gcc 16.2.0 上编译验证）
源文件编码：UTF-8；程序内部统一按 UTF-8 处理，控制台输出不会乱码

2. 编译
```bat
gcc -O2 -std=c11 -Wall -o wordfreq.exe wordfreq.c
```
也可以直接用最朴素的写法（不指定标准）：
```bat
gcc wordfreq.c -o wordfreq.exe
```
> 源码以 UTF-8 保存。若编译器提示字符集问题，可显式指定：
> `gcc -finput-charset=UTF-8 -fexec-charset=UTF-8 -o wordfreq.exe wordfreq.c`

3. 使用
```
程序名.exe <指定文件路径> -n <数量>
```
```bat
wordfreq.exe D:\data\article.txt -n 10
wordfreq.exe "D:\我的文档\课文 01.txt" -n 5
```
路径中含空格或中文时，用英文双引号把路径括起来即可。
数量 `N` 只接受阿拉伯数字组成的正整数。
一次最多输出 200 个词；`N` 大于实际词数时输出全部词汇。
输出格式
```
序号. 单词 数量
```
示例文件 `article.txt`：
```
红红火火，星期五。星期五真好！
The quick brown fox jumps over the lazy dog.
The dog sleeps. The end.
Привет мир, Привет.
123 456 7.5 !!! ???
```
执行 `wordfreq.exe article.txt -n 8`，输出：
```
1. the 4
2. 红 2
3. 火 2
4. 星 2
5. 期 2
6. 五 2
7. dog 2
8. Привет 2
```
可以看到：`the`（不分大小写）出现 4 次排第一；同为 2 次的「红、火、星、期、五」
属于中文，排在英文 `dog` 和俄语 `Привет` 之前；中文内部按首次出现的先后排列
（红 → 火 → 星 → 期 → 五）；数字、标点、`7.5`、`!!!` 都没有被统计。

4. 规则说明
以下逐条对应文档要求，均为 `wordfreq.c` 中的实际实现。
4.1 数量参数
输入	结果
`-n 10`	正常统计，输出前 10 个
`-n 0`、`-n -5`、`-n abc`、`-n 3.5`、缺 `-n`、参数个数不对	`数量有误`
`-n 201` 及以上	`数量超限`（一次最多输出 200 个词）
`N` 大于实际词数	输出全部词后直接结束
4.2 英文
不区分大小写：`The`、`the`、`THE` 是同一个词，统一按小写统计和显示。
按「单词」统计，不按单字符统计：以空格和标点作为分隔符，
取最长的连续字母串作为一个词。
词频相同时，按首字母 ASCII 码逐字符比较；若一方先结束（如 `help` 与 `helpful`），
短的一方在前 → `help` 排在 `helpful` 前面。
4.3 中文
逐字统计：`星期五` → 星 1 次、期 1 次、五 1 次。
频次相同的字，按首次出现的先后排序：`红红火火` → 红、火 频次相同，红先出现，红在前。
4.4 特殊符号与阿拉伯数字
不计入统计，只在分词时起分隔作用。
例如 `7.5`、`123`、`!!!`、`???`、`——`、全角标点等都会被视为分隔符。
4.5 其他语言（俄语、德语等）
只按「单词」计：以空格或标点为分隔。
不做大小写合并（`Der` 与 `der` 视为两个词）。
频次相同时，先出现的在前。
4.6 多语种混排
频次相同时的排序优先级为：
```
中文  →  英文  →  其他语言（其他语言内部按首次出现排序）
```
4.7 文件与编码
情况	输出
文件不存在、路径错误、打不开、路径是目录	`文件异常`
不是纯文本文件（`.docx` / `.xlsx` / `.pdf` / 压缩包 / 图片等二进制文件）	`文件异常`，并在 stderr 提示「请先另存为 .txt」
空白文件（0 字节，或只有空白/符号/数字，没有可统计的词）	`该文件为空`
程序会先按文件头识别二进制格式（ZIP、OLE2、PDF、gzip），再看内容的控制字符占比；
只要判定不是文本，就直接拒绝，不会把压缩包里的二进制字节当成文字去统计。
源文件编码自动识别，无需转换：UTF-8、带 BOM 的 UTF-8、UTF-16（LE/BE）、
GBK（中文 Windows 记事本的 ANSI 格式） 都能正确读取。
4.8 乱码处理
程序内部统一使用 UTF-8 字符串。
启动时调用 `SetConsoleOutputCP(CP_UTF8)`，控制台按 UTF-8 解释输出，中文不会乱码。
输出重定向到文件时同样是 UTF-8，用记事本、VS Code 打开都正常。

5. 错误提示与退出码
提示	触发条件	退出码
`数量有误`	数量不是阿拉伯数字正整数、缺 `-n`、参数个数不对	1
`数量超限`	请求的数量大于 200	1
`文件异常`	文件不存在 / 打不开 / 是目录 / 不是纯文本文件（如 .docx）	1
`该文件为空`	空文件，或没有任何可统计的词	0
`内存不足`	内存分配失败（极端情况）	1
所有提示都输出到标准输出（stdout），方便重定向和自动判题；用法提示额外输出到
标准错误（stderr），不影响标准输出的内容。

6. 实现要点
分词（`tokenize`）：按 UTF-8 码点逐字符扫描——
ASCII 字母 → 累积成英文单词；
汉字（CJK 基本区、扩展 A、兼容区、扩展 B 及以上）→ 单独成一个「字词」；
其他语言的字母（西里尔、希腊、拉丁扩展、假名、谚文等）→ 累积成单词；
数字、符号、空白、非法字节 → 一律作为分隔符。
统计（`table_add`）：开放寻址哈希表（FNV-1a 哈希，负载因子 0.7 自动扩容），
词条记录「次数」和「首次出现序号」，大文件也不会退化成线性查找。
排序（`cmp_entry`）：`qsort` + 四级比较器——
频次降序 → 类别（中文/英文/其他）→ 英文按 `strcmp` → 其余按首次出现序号。
其中 `strcmp` 天然满足「短词（前缀）在前」。
编码识别（`load_utf8_file`）：BOM 判别（UTF-8 / UTF-16）→ 严格 UTF-8 校验 →
失败则按 GBK 转 UTF-8（Windows API 转换，UTF-16 由手写代码转换，兼容代理对）。
防乱码：`SetConsoleOutputCP(CP_UTF8)` + 全程 UTF-8 字节输出。

8. 两点说明
输出空格：文档正文写的是「序号.  单词 数量」（两个空格），但示例是
`1. 我 666`（一个空格），本程序按示例使用一个空格。若需要两个空格，
修改 `wordfreq.c` 末尾的
`printf("%d. %s %lld\n", (int)(i + 1), arr[i].word, arr[i].count);` 即可。
文档版本：当前 `D:\词频统计计划.docx` 中已没有旧版的
「一句话最多 400 字节 / 句子过长」这一条，因此程序不限制句子长度。
若该要求仍需保留，可据此补充：按换行和 `。！？；.!?;` 切句，超 400 字节输出
`句子过长` 并结束。

9. 常见问题
Q1：为什么拿 `.docx` 去统计，结果是一堆单个字母（g、j、o……）？
因为 `.docx` 不是文本文件，它本质是一个 ZIP 压缩包（文件头是 `PK\x03\x04`），
里面装着 `word/document.xml`、样式、主题等一堆 XML，正文只是其中一小段。
把压缩包当成文本读，会发生这样的事：
程序按字节读入整个文件；
UTF-8 校验失败（压缩数据不是合法 UTF-8）；
于是回退按 GBK 解码，二进制字节被硬拆成大量随机汉字 + 零散的 ASCII 字母；
汉字有成千上万个取值、每个大多只出现一两次，而 ASCII 字母只有 26 个、
每个都能撞上几十次，所以高频榜上全是单字母。
而截图里的「空.docx」其实一点也不空：即使正文一个字都没写，Word 也会把
约 13 KB 的 ZIP 结构（`[Content_Types].xml`、`word/document.xml`、样式表……）写进文件，
所以它既不是 0 字节、也不是空白文本。
旧版程序对这类文件不设防，会把二进制垃圾当成文本统计；现在的版本会先识别文件类型，
直接输出 `文件异常`，并在 stderr 给出「请先另存为 .txt」的提示。
Q2：那要统计 Word 里的文章（比如《离骚》）怎么办？
先用 Word 另存为纯文本：文件 → 另存为 → 纯文本 (*.txt)，
编码选 UTF-8 或默认 ANSI 都可以（程序两种都能识别），再统计即可：
```bat
wordfreq.exe D:\离骚.txt -n 10
```
把 `离骚.docx` 转成 txt 后实测（正文共 3063 字），输出为：
```
1. 兮 187
2. 之 98
3. 以 78
4. 而 73
5. 余 51
6. 不 41
7. 其 41
8. 吾 26
9. 为 23
10. 夫 21
```
「兮」「之」「而」正是《离骚》里最典型的虚词，说明统计结果是对的。
